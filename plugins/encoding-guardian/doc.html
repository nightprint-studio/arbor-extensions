Encoding Guardian

Catches encoding hazards before they reach a commit: UTF-8/CP1252 mojibake (sequences like â€¦ originally …), invalid bytes in the project's declared charset, BOM mismatches, and line-ending mismatches. Each project defines its own encoding contract — Arbor is not all UTF-8.

How it runs

  • corvus:pre_commit — when this project is opted in, scans the staged set (exactly what git diff --cached --name-only would list) against the project's charset / EOL rules and returns a veto string listing the offenders. The host aborts the commit and surfaces the message. Working-tree garbage you haven't git add-ed is ignored.
  • The hook is opt-in per project. New repos default to disabled — toggle Enable pre-commit encoding check in the Command Palette: Encoding Guardian: Project settings.
  • A global kill switch (Master kill switch) lives in the Plugin Manager gear-icon settings — turning it off disables the hook everywhere, regardless of any per-project flag.

Command Palette

  • Encoding Guardian: Project settings — per-repository encoding contract for the active repo: enable the pre-commit check, pick the charset and line ending, choose which checks block, and tune the scan scope. These are scoped to the open repo, which is why they live here rather than in the (global) gear-icon settings.
  • Encoding Guardian: Scan project — manual scan that shows a progress card while it walks the tree, then a result modal with summary counters, the file list and per-file issues. The modal also states the effective per-project contract (charset / EOL) the scan ran with, so it's clear which settings produced the verdict.
  • Encoding Guardian: Fix mojibake — auto-repairs every known mojibake sequence (…, —, ', ", •, →, ─) in the active repo. Other issues (BOM, EOL, invalid bytes) need a manual fix or an .editorconfig rule.

What gets checked

  • Mojibake — nine known UTF-8/CP1252 sequences plus a catch-all exotic counter for the â€ prefix that indicates corruption even when the third byte isn't one we recognise.
  • Charset — when the project is declared utf-8, any file containing invalid UTF-8 sequences (or a UTF-16 BOM) is flagged. When it's declared windows-1252, files carrying a byte undefined in CP1252 (0x81, 0x8D, 0x8F, 0x90, 0x9D) are flagged, each offender listed with its byte and line:column. Single-byte charsets that map every byte (latin1) have nothing to validate here. Files are read as raw bytes, so non-UTF-8 content is inspected rather than skipped.
  • BOM — UTF-8 BOM presence is checked against the project's declared expectation. Disabled by default; enable when the team has a strong "no BOM" or "BOM required" rule.
  • EOL — first 64 KiB of each file is sampled to decide whether it uses lf, crlf, or mixes both. Compared against the project's declared expectation when not set to any.

Per-project encoding

Settings persist under <repo>/.arbor/plugins/encoding-guardian/project.json so each repo carries its own charset / EOL / scope. A legacy CP1252 project can keep its rules without affecting any other repo open in Arbor.

Required permissions

  • fs = "write" — scan reads source files; the fix command rewrites them.
  • git = "read" — resolves the active repo root.

Limitations

  • The scan walks the whole working tree (excluding common build directories — node_modules, target, dist, build, .git, .next, .svelte-kit) and stops at the safety cap (max files, default 5000). It does not currently honour .gitignore beyond those common excludes — declare extra patterns in the Exclude globs setting.
  • Auto-fix only repairs the known mojibake sequences. Exotic â€<X> sequences are surfaced in the scan modal but not auto-rewritten — fix them by hand to avoid guessing.
