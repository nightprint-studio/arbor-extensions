Google Cloud Storage

Adds GCS buckets to Arbor's cloud panel. This package is the backend — the panel, the connection list and the settings form live in the cloud-storage package, which this one depends on. Installing this without that one gives you a provider with nothing to drive it; the Marketplace offers to install both.

Connecting

Open Cloud → Connections → Add, pick Google Cloud Storage, and sign in. The access token is stored in your operating system's keychain, never in a settings file and never inside this package's folder.

Where the token comes from

The cloud panel runs the sign-in and stores the result with arbor.credentials.set("oauth", token) — into this package's slot, which is the only one this backend can read. Nothing outside a package writes into its namespace, including Arbor itself, so a connection made before this backend was installed needs one reconnect before it can serve it.

Until then the panel keeps working: Arbor falls back to its own built-in implementation rather than failing, so installing this package can never break a connection that was already working.

What it can reach

Exactly two things, both declared in its manifest and both shown to you when you install it:

  • Network: googleapis.com and its subdomains. Nothing else — a request to any other host is refused by Arbor before it is sent.
  • One credential slot, the Google access token. It can read and write that slot and no other, and it cannot name the credentials Arbor keeps for itself (your git provider tokens, your issue-tracker keys) at all.

The backend is a sandboxed WebAssembly component: it has no filesystem, opens no sockets, and never handles TLS. Every request is performed by Arbor on its behalf, which is what makes the two limits above enforced rather than promised.

What it supports

OperationNotes
BrowseFolders are synthesised from key prefixes — object storage has no directories. A folder row has no size or date because there is none to report.
DownloadRead in ranges, so progress and Cancel work exactly as they do without this package — the transfer is Arbor's, only the bytes come from here.
UploadWhole-object, so files up to 64 MB come through this backend and anything larger is streamed by Arbor's built-in path instead. The upload works either way; only which side moves the bytes changes.
DeleteRemoving a key that is not there succeeds.
CopyServer-side — the bytes never travel through your machine.
